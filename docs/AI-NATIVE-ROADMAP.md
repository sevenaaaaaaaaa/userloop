# UserLoop · AI Native 路线（双视角：使用者 / 终端用户）

> 本质：UserLoop 是 MA（Marketing Automation）工具。传统 MA = 人写规则 → 固定动作 → 报表；
> AI Native MA = **目标驱动 → AI 规划 → 执行 → 自评 → 迭代**，人从"配置者"变为"目标与边界设定者"。
> 本文按两个视角盘点差距与机会，并标注现状与优先级。

## 一、能力现状（已交付）

事件总线 / 自有 CDP-lite（8 阶段旅程 + 断点）/ Loop 引擎（模板 + 验证回流）/ Canvas 图执行 /
AI 大脑（NBA 决策 + 频控/静默期/预算 + 风险审批门）/ 触点（邮件 HTML+追踪+退订+抑制、短信三供应商、
H5 双引擎 + 六维千面、IM、HubSpot、OpenFlow/MFlow 互通）/ A/B 版式实验（显著性 + 提升）/
身份图谱 / 验收入口（控制台、A-B、AI 决策、MCP 只读回读）。

## 二、使用者（运营人员）视角

| # | 机会 | 现状 | 优先级 |
|---|---|---|---|
| A1 | **Copilot：一句话建流程**（自然语言 → Loop/Canvas 草稿 → 校验 → 一键启用） | 只能手工拼模板/画布 | **P0（本轮已做）** |
| A2 | **AI 周报复盘**：自动产出"哪个 Loop 有效、哪个阶段漏损最大、下一步做什么" | 有 feedback 数据但无自动洞察 | P0 |
| A3 | **自然语言分群**："最近 7 天加购未付且客单 >200 的用户" → segment 规则 | 仅阶段/静态 | P1 |
| A4 | **发前质检门**：退订链接/占位符/垃圾词/断链/移动端/送达风险 | 无 | **P0（本轮已做）** |
| A5 | **交付物协作**：审批、评论、变更审计可视化 | 有审批门，缺协作面 | P1 |
| A6 | **行业模板包**：电商/教育/SaaS/本地服务一键导入（MFlow 行业包可借鉴） | 内置 5 个通用模板 | P1 |
| A7 | **成本与健康看板**：AI tokens、短信条数、退信/投诉、渠道健康度 | 有 outbox，无看板 | P1 |
| A8 | **多租户 / 多品牌 / i18n**（面向国内外） | 单工作区，时区可配 | P2 |
| A9 | **合规中心**：同意管理（consent）、DSAR 导出/删除、保留期看板 | 有 prune，无 consent/DSAR | P1（出海必需） |

## 三、终端用户（被运营者）视角 —— 体验即留存

| # | 机会 | 现状 | 优先级 |
|---|---|---|---|
| B1 | **跨渠道全局频控**：不是按渠道各限一次，而是"这个人 24h 内只被打扰 1 次" | 频控在 AI 护栏层，未覆盖模板 Loop | P0 |
| B2 | **发送时机优化（STO）**：按用户历史活跃时段发送，而非统一静默期 | 仅静默期 22–08 | P1 |
| B3 | **偏好中心**：用户自选渠道/频次/兴趣；一键暂停而非只能退订 | 仅邮件退订/短信退订 | P1 |
| B4 | **跨触点记忆**：邮件说"你卡在第 2 步"，H5 打开后直接续上 | H5 有阶段参数，无跨触点上下文 | P1 |
| B5 | **Next Best Channel**：同一意图自动选渠道（打开率低→改短信/微信） | 渠道由模板写死 | P1 |
| B6 | **对话式触达**：微信/WhatsApp/站内 AI 跟进（双向），而非单向群发 | OpenFlow 已能收消息回调，未接 AI 回复 | P2 |
| B7 | **可解释性**：为什么给我看这个（"因为你上次加购未付"） | H5 千面有横幅，未系统化 | P2 |
| B8 | **退出意图 / 停留强化**：内置页已支持 N 秒强化 CTA | ✅ 已有（可扩到滚动/退出） | — |

## 四、AI Native 范式差异（本质层面）

| 维度 | 传统 MA | AI Native MA | UserLoop 位置 |
|---|---|---|---|
| 起点 | 人写规则 | 人给目标 + 边界 | 模板为主，AI 大脑已能决策 |
| 编排 | 手工画布 | **自然语言生成 + 人审** | A1 本轮补上 |
| 内容 | 人写文案 | **AI 生成 + 质检门 + A/B 自提升** | 有 AI 文案 + A/B 提升，缺质检门（A4 本轮补） |
| 优化 | 人看报表调参 | **自评 → 自动迭代** | 有验证回流，缺自动改流程 |
| 预测 | 无 | churn / LTV / 购买倾向 | 无（仅规则统计） |
| 时机 | 固定时间 | **STO + 个体最优时机** | 仅静默期 |
| 触达形态 | 群发 | **对话 + 个体连续性** | 单向为主 |

## 五、路线图（按投入产出排序）

- **P0（本轮）**：A1 Copilot 自然语言建流程；A4 发前质检门（同时保护终端用户，减少骚扰与投诉）
- **P1（下一步建议）**：B1 跨渠道全局频控 → B5 Next Best Channel（同一套"渠道选择器"）；A2 AI 周报；B2 STO；
  A9 合规中心（同意/DSAR）；A3 自然语言分群
- **P2**：预测层（churn/LTV 评分 → 驱动 AI 大脑与分群）、B6 对话式触达、A8 多租户/i18n

## 六、判断标准（为什么这么排序）

1. **先解决"人怎么用"**：MA 工具失败的主因不是缺功能，而是运营不会配、配错、配了不放心 → Copilot + 质检门
2. **再解决"用户体验"**：跨渠道骚扰是 MA 最大的隐性成本（退订/投诉/品牌损伤）→ 全局频控 + 渠道选择
3. **最后做预测/对话**：需要数据积累（我们已有事件量与回流数据），且需外部凭据（微信/WhatsApp）
